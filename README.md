# Мишка-шкряботушка

Telegram-бот, який приймає документи від користувачів і відповідає на запитання за їхнім змістом українською мовою, завжди вказуючи джерело.

**Python 3.12 · aiogram 3 · PostgreSQL + pgvector · Groq LLM · Docker Compose**

## Можливості

- Приймає PDF, DOCX і TXT (до 20 МБ). Скановані PDF без текстового шару не підтримуються, бот пояснює це користувачеві.
- Під час першого завантаження питає справжнє ім'я користувача й підписує ним усі його документи.
- Документи спільні для всіх: питання шукає відповідь в усіх документах.
- У відповіді вказує назву документа, ім'я завантажувача та дату й час (за київським часом). Для документів Лісового архіву показує лише «Лісовий архів» і назву.
- Якщо відповіді немає, чесно про це каже і нічого не вигадує. Якщо інформація неповна, пояснює, чого бракує.
- Конкретніша порада має пріоритет над загальнішою (рукавичка → частина лісу → увесь ліс). Загальну можна додати лише як пояснення, якщо вона не суперечить конкретній. Якщо однаково конкретні джерела суперечать одне одному, бот показує обидва й прямо про це каже.
- Документи й метадані зберігаються після перезапуску. Історія запитань не зберігається. Видалення документів у першій версії немає.
- Команди: `/start`, `/help`.

## Як це працює

```
Telegram ──► aiogram (хендлери, FSM)
                 │
     ┌───────────┼─────────────┐
     ▼           ▼             ▼
 витяг тексту  індексація   пошук + відповідь
 pypdf/docx    чанки +      гібридний пошук,
               ембединги +  правила пріоритету,
               розмітка     Groq
                 │             │
                 ▼             ▼
         PostgreSQL + pgvector   Docker volume (оригінали файлів)
```

### Завантаження документа

1. Перевірка формату й розміру. Новий користувач спершу вводить ім'я (стан FSM), файл скачується після цього.
2. Дублікати відсікаються за SHA-256 файлу.
3. Текст витягується з файлу в окремому потоці, щоб не блокувати бота. Для TXT пробується UTF-8, потім CP1251. Нечитабельні файли в базу не потрапляють.
4. Текст ріжеться на шматки: одна порада = один шматок (рядок; задовгі рядки ріжуться по реченнях). Це потрібно, щоб рівень конкретності ставився кожній пораді окремо.
5. Для шматків рахуються ембединги (локальна модель `paraphrase-multilingual-MiniLM-L12-v2`, 384 виміри).
6. Groq розмічає кожен шматок: рівень (1 рукавичка, 2 частина лісу, 3 увесь ліс) і мітку. Якщо для кого порада, незрозуміло, модель не вгадує: рівень лишається порожнім, а бот питає завантажувача.

### Пошук

Гібридний: найближчі за змістом шматки (cosine за pgvector, індекс HNSW) і схожі за словами (триграми `pg_trgm`). Результати зливаються через Reciprocal Rank Fusion. Далі відсікається нерелевантне (абсолютний поріг плюс відступ від найкращого збігу), і лише після цього шматки впорядковуються від конкретних до загальних.

### Відповідь

Groq отримує питання та знайдені шматки й повертає JSON: основну пораду, доповнення, прапорець суперечності й те, чого бракує. Далі працює код:

- джерело (документ, автор, час) береться з бази за номером шматка, модель не може його вигадати;
- правила пріоритету застосовуються в коді, а не лише в промпті;
- якщо пошук нічого не знайшов, LLM не викликається взагалі.

## Запуск

Потрібен Docker та токен бота від [@BotFather](https://t.me/BotFather) і ключ [Groq](https://console.groq.com/keys).

```bash
cp .env.example .env        # у PowerShell: copy .env.example .env
# впиши BOT_TOKEN, GROQ_API_KEY і свій POSTGRES_PASSWORD (той самий у DATABASE_URL)
docker compose up --build
```

Міграції застосовуються автоматично під час старту. Під час першого запуску завантажується модель ембедингів (~220 МБ), вона кешується в Docker volume.

| Змінна | Призначення |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота |
| `GROQ_API_KEY` | ключ Groq |
| `GROQ_MODEL` | модель Groq (необов'язково, за замовчуванням `llama-3.3-70b-versatile`) |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | доступ до БД |
| `DATABASE_URL` | рядок підключення бота до БД |
| `TEST_DATABASE_URL` | БД для тестів (див. нижче) |

## Лісовий архів

Стандартні документи завантажуються заздалегідь:

1. Поклади файли в папку `archive/` біля `compose.yaml`.
2. `docker compose exec bot python -m app.scripts.seed_archive /archive`

Скрипт безпечно запускати повторно: файли, що вже є, пропускаються за SHA-256. Документи архіву зберігаються без завантажувача. Шматки з неясною областю лишаються без рівня, бо питати нікого.

Підібрати пороги релевантності можна так: `docker compose exec bot python -m app.scripts.search_debug "питання"`.

## Тести

```bash
pip install -e ".[dev]"
pytest
```

Тести, що потребують бази (репозиторії, пошук, архів), працюють із реальним Postgres і пропускаються без `TEST_DATABASE_URL`:

```bash
docker compose up -d db
docker compose exec db createdb -U mishka mishka_test
# PowerShell: $env:TEST_DATABASE_URL="postgresql+asyncpg://mishka:ПАРОЛЬ@localhost:5432/mishka_test"
export TEST_DATABASE_URL=postgresql+asyncpg://mishka:ПАРОЛЬ@localhost:5432/mishka_test
pytest
```

Groq і модель ембедингів у тестах підмінені заглушками, тому зовнішніх викликів немає.

## Структура

```
app/
  bot/            хендлери aiogram, стани FSM
  services/       витяг тексту, чанкінг, ембединги, клієнт Groq,
                  розмітка рівнів, пошук, формування відповіді
  repositories/   доступ до БД (користувачі, документи, шматки)
  db/             моделі SQLAlchemy, сесії
  scripts/        seed_archive, search_debug
migrations/       Alembic
tests/
```

## Рішення й обмеження

- **Одна порада = один шматок.** Якщо в одному рядку кілька коротких речень, вони мають спільний рівень конкретності.
- **Вміст документів потрапляє в промпт.** Захист обмежений: Groq повертає лише JSON, джерела підставляє код, а права бота мінімальні.
- **Пороги релевантності** підібрані емпірично на малому наборі документів. На великому архіві їх варто перевірити через `search_debug`.
- **Стан «чекаю ім'я»** зберігається в пам'яті процесу: після перезапуску бота людина введе ім'я знову.
- **Обробка довгих документів** відбувається синхронно, поки користувач чекає. Для великого потоку файлів її варто винести у фонову чергу.
- Скани, видалення документів та історія запитань свідомо не входять до першої версії.
